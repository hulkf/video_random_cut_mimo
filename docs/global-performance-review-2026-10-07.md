# 全项目批处理性能审计（2026-10-07）

## 范围与机器

检查了注册表中的 17 个页面、headless_operations 正式入口、任务中心执行边界和共用 FFmpeg 执行器。
本次修复基于 `2249ccd6`；该提交已包含视频拼接和模板流水线优化，详见 `concat-performance-2026-10-07.md`。
当前机器为 Intel Core Ultra 9 185H（16 核 / 22 逻辑线程）、约 31.4 GiB 内存、Intel Arc 集显。
未把 QSV 强制设为默认：上一轮本机短视频测试未显示其优于当前软件路径。

## 已修复的问题

| 功能 | 发现的问题 | 当前处理 |
|---|---|---|
| 视频尺寸 | GUI 和正式工具重复实现串行循环 | 统一到核心批处理；默认两路；单文件路径修正；派发前预留输出名 |
| 音频混剪 | 串行、每次重复扫描切片、每片段创建去音频副本；超长候选可能无限重试 | 一次扫描和时长缓存、默认两路；直接把原片交给仅输出视频的拼接器；候选无论接受与否都推进 |
| 视频混剪 | 每个结果串行；零时长素材可能导致填充循环不退出 | 默认两路，批次开始统一探测时长；过滤非有限/非正时长；预留输出名 |
| 视频切片 | 正式入口串行；GUI 乱序完成时续跑位置可能跳过未完成输入 | 正式入口默认两路；GUI 只推进连续完成位置；拒绝同名不同扩展名冲突和无效切片时长 |
| 视频截图 | GUI/core 重复实现逐帧串行抽取，单文件 GUI 输入失效 | 统一抽帧；每次最多两路、每进程两线程；支持单文件；既有图片自动避让 |
| 视频裂变 | 默认软件并发最多八路且单进程线程无预算；一次提交全部 futures；尚未落盘的重名输出竞争 | 实测选择软件默认四路；每任务最多四线程；有界提交；派发前预留名称；回调统一回调用线程 |
| 文字识别 | 一次排队全部输入；少量文件也创建多份模型；固定抽帧目录有覆盖等待/旧帧残留问题 | 活跃任务数封顶；进程数不超过输入数；每次独立帧目录；显式覆盖仅本次目录，抽帧线程受限 |
| 人脸识别 | 一次排队全部输入，停止后难及时取消排队任务 | 有界派发；进程数不超过输入数；保留每进程模型复用和原有提前判定 |
| 开拍云端 | 全批 futures 提前入队，GUI 停止后排队项仍可能调用外部服务 | 有界派发；调用前再检查停止；保留原并发配置、持久化云任务和结果顺序 |

本地文件并发保持输入顺序返回结果，进度回调在调用线程执行；异常或取消停止继续派发，已运行任务收尾后才释放临时输入。
FFmpeg 线程预算使用任务上下文，不修改用户配置，不改变独立单任务的显式线程参数。
对支持 `batch_workers` 的正式操作，可传 1、2、3；裂变继续使用 `max_workers`。

## 其余功能审计结论

| 功能 | 当前判断 / 本次边界 |
|---|---|
| 视频拼接、模板 | 已复用上一轮两路并发、规范素材复用和合并最终缩放；本次全量回归覆盖相关测试 |
| 视频优化（Wink） | 外部执行器带实例进程状态；保留逐文件与跳过已有结果逻辑，未验证多实例吞吐，不擅自并行 |
| 去关键词 | 批次复用 ASR 模型；保留模型推理串行，未做真实模型性能基准 |
| 视频字幕 | ONNX/Sherpa 路径批次复用模型；Whisper 子进程仍可能逐文件重新加载，是后续有价值的专项优化点，尚未改成长驻服务 |
| 音色复刻 | 复用服务与延迟加载的识别器，替换音轨复用视频流；保留模型串行，未测试多请求服务并发 |
| 视频下载 | 复用浏览器会话；Playwright 会话有线程边界，未把同一页面跨线程共享；网络吞吐未做实测 |
| 设置 | 无批处理热路径；未改变本地配置 |
| 素材归档 | 以复制/解包 I/O 为主，保持原文件管理语义，本次不增加多路磁盘读写 |
| 任务中心 | 同一计划的步骤有结果依赖，应顺序执行；文件并行放在步骤内部。已有输出目录资源锁仍保留 |

当前预算按单个批次生效，尚不是跨 GUI 页面、跨任务进程的整机资源调度器。
不同任务同时运行时仍可能叠加占用；本次不宣称解决了跨进程全局自适应调度。
OCR、人脸、语音模型和云端服务未进行在线业务验收；云端不产生实际付费调用。

## 本机对照测试

旧版本从 Git `2249ccd6` 提取到系统临时目录；新旧均通过正式 CLI `run --request -`，参数即时生成并通过 stdin 提交，stdout JSON 和 stderr 分开捕获。
素材是 3 个 720×1280、30 fps、4 秒动态测试视频（带音频）；音频混剪使用 3 个 12 秒音频；截图每视频 4 张；切片每段 2 秒。
时间为完整 CLI 墙钟时间，包含启动和探测。每项单轮对照，随机内容、温度与系统负载会引入波动，不能当作所有业务素材的固定提速比例。

| 操作 | 旧版秒数 | 本次秒数 | 耗时减少 |
|---|---:|---:|---:|
| 尺寸转换，3 个结果 | 3.701 | 2.446 | 33.9% |
| 音频混剪，3 个结果 | 13.213 | 9.360 | 29.2% |
| 视频混剪，3 个结果 | 13.678 | 8.285 | 39.4% |
| 切片，6 个结果 | 4.667 | 3.928 | 15.8% |
| 截图，12 张 | 5.250 | 4.886 | 6.9% |

裂变单独校准：3 个输入各生成 3 份，共 9 个结果。旧版 4.575 秒；新代码并发 2/3/4 分别 5.933/4.427/4.147 秒。
因此否决两路默认值，采用四路。复测旧版 5.106 秒、新默认 4.845 秒，改善约 5.1%；首轮四路改善约 9.4%。
初始 3 结果两路实验也出现回退（2.464 → 2.752 秒），没有将其作为最终配置交付。
