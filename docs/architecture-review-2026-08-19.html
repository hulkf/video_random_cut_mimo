16个标签页功能模块
19处重复的视频格式列表
17个手写线程类（每个页各写一遍）
4+份各自为政的 ffprobe 探测实现

一、结论先行（TL;DR）

项目功能齐全，但属于典型的"功能先行、无公共层"架构——16 个标签页各自从零搭 UI、各自写线程、各自调 ffmpeg。你反馈的三个问题根因非常集中：

  • 前端复用不足 → 没有公共 UI 基类，每个页面重复实现"路径选择 / 进度条 / 日志 / 线程"，主题样式坑（如输入框无边框）被复制修了三层。
  • 输入输出规则冗余 → 视频格式列表重复 19 处、ffprobe 探测 4 份、9:16 规格处理 3 份还不一致，改一个规则要改十几个文件。
  • 处理速度慢 → 22 核 CPU + NVENC 显卡的机器，只有「视频裂变」一个模块用了硬件编码和并发，其余全部在跑单线程软件编码，还有大量无意义的重复编码。

核心建议：抽一层「公共组件 + 公共后端」，新页面从 ~500 行降到 ~150 行；把裂变模块已验证的硬件编码方案推广到全局，多数模块可提速 2~6 倍。预计分 3 个阶段、5~6 周内平稳落地，每步独立提交，不搞推倒重来。

二、现状诊断：三大问题的根因

问题 1：前端模块复用不足 根因：无公共 UI 基类

  • 17 个线程类散落各处：每个标签页都手写一个 xxxWorker(QThread)，信号签名几乎一样（进度/完成/报错），但每个页面重写一遍，出问题要逐页修。
  • 输入框样式坑修了三层：qt-material 主题下输入框没边框的问题，全局样式修了一遍、裂变页又加了一层、下载页再内联一段样式（18 处 !important）——新页面每次都要重新踩一遍这个坑。
  • "路径选择 + 浏览按钮 + 保存配置"整段重复：至少 4 个页面逐字重复这一段代码；路径去引号的工具函数也有两份，其余页面各写各的。
  • 进度条 + 状态文字组件：16 个页面全部重复出现，写法细节各异。

问题 2：输入输出规则冗余 根因：规则散落、无单点维护

  • 视频格式列表重复 19 处：改一个支持的格式要改 19 个文件，漏一个就出现"这个页面能选、那个页面选不了"。
  • 媒体探测实现 4 份：同一个"读视频宽高/时长/码流"的功能有 4 个不同版本，行为还不完全一致；视频时长工具甚至有两份。
  • 9:16 / 1080×1920 规格处理 3 份且互相不一致：模糊填充背景（把横屏视频垫成竖屏）有 3 套实现，参数、画质行为各不相同。
  • 千川硬性校验项手工重复：输出视频必须 SAR=1:1（否则千川报"尺寸不符合规范"，历史上出过 2943:2944 的事故）——这条铁律在 6 个地方手工写，漏一处就翻车。
  • 输出命名规则全部内联：每个模块自己定一套命名，五花八门；路径/空值校验在每个页面的"开始"按钮里手写一遍弹窗。

问题 3：视频处理速度慢 根因：四层瓶颈叠加

瓶颈层现状影响
① 编码器只有「视频裂变」做了 NVENC 硬件编码自动探测（实测比软件快 6.3 倍），其余所有模块硬编码 libx264 软件编码——22 核 + 独显的机器在跑单线程软件压片▲ 单文件 2~6×
② 串行执行批量处理全部一个接一个排队跑（循环串行），只有裂变用了并发；整批 100 个视频 = 100 倍串行时间▲ 批量 4~8×
③ 无效重编码拼接模块：比例不对的先"模糊垫底"重编码一次，拼的时候又重编码一次 = 同一段视频压两遍；音频也全部重新编码（本可直接复制）▲ 5~30%
④ 无进度/无缓存全项目没有 ffmpeg 进度解析（长视频 UI 一直显示 0%）；没有缓存：输出文件存在也照样重跑全量重做；批量时每个文件反复探测元数据▲ 体验 + 10~30%

三、公共模块抽象方案（核心建议）

目标架构一句话："页面只负责布局和交互，公共组件提供统一零件，后端公共层统一干活"。所有新页面直接拼装公共零件，不再从零写。

前端公共组件（解决问题 1、2 的 UI 部分）

组件干什么用的（大白话）收益
BaseTab 基类所有页面的"公共骨架"：统一开始/停止按钮状态、统一管理后台线程的开启和关闭（现在关窗口要 15 个页面各写一遍清理代码）、统一异常处理新页面样板代码 -30%+
路径选择控件"选文件夹/选文件"这一行，一个零件搞定，自动去引号、自动记住上次配置；输入框边框修复只在这里写一份，全项目生效消灭"三保险"重复
进度面板 / 日志 / 结果表格进度条+百分比+状态行、滚动日志、结果列表（暗色样式只写一份），16 个页面直接拼装交互体验统一
通用线程 BaseWorker一个标准线程模板，统一"进度/完成/报错/停止"四个信号协议，17 个手写线程类收敛成薄薄一层子类线程逻辑只调一处

后端公共层（解决问题 2、3 的核心）

模块干什么用的（大白话）收益
统一 ffmpeg 执行器所有页面调 ffmpeg 只走这一个入口：自动隐藏黑窗、能报真实进度百分比、支持停止/中断、超时自动清理；编码参数由"编码策略"统一注入一处实现全项目受益
媒体探测 + 缓存读视频宽高/时长/码流只此一份，批量处理时同一文件只探测一次（结果缓存），收敛现有 4 份实现批量省 10~30% 时间
编码策略 EncoderPolicy把「视频裂变」已验证的 NVENC 硬件编码探测逻辑（0.3 秒试压、被占用自动回退）提出来全局共用——这是提速最大的一招除裂变外全部模块自动 2~6×
输出规格校验器千川规格（9:16 / 1080×1920 / SAR=1 / 偶数尺寸 / H.264）单点定义；三份模糊填充实现合并成一份；统一输出命名规则单点维护，杜绝 SAR 事故复发
格式列表 / 路径工具 / 文件收集视频格式清单只写一处（现在 19 处）、路径去引号/防重名统一、批量扫文件统一——改格式只改一个文件改规则只改一处

预期整体效果：新加一个标签页从约 500 行代码降到约 150 行；输入输出规则全项目只维护一处；新页面不再踩旧坑。

四、性能优化清单（按性价比排序）

#优化项预期提速改动成本风险
1硬件编码全局接入（把裂变的 NVENC 探测逻辑推广到所有模块，替换 libx264 硬编码）单文件 2~6×低中（需回退+并发限制）
2音频直接复制（源音频能复制就不重新编码，现在几乎全部重压）5~15%极低低
3批量任务并发（把"一个个排队跑"改成"多个一起跑"，裂变已有成熟模式）批量 4~8×中中
4媒体探测缓存（同文件只探测一次）批量 10~30%低低
5消除双重编码（拼接场景：同一段视频不再压两遍；纯裁剪用流复制）拼接 3~10×中中
6单文件真实进度（UI 显示百分比，不再"卡在 0%"）体验提升低低
7断点续跑（输出已存在且参数没变就跳过，重跑接近秒过）重跑秒过中低

建议执行顺序：先做 1+2+4（低风险高收益，约 1 周全局生效），再做 3 并发，最后 5/6/7。

五、分阶段落地路线图

1阶段

公共层落地（只新增、不改旧代码）约 1~2 周每步独立提交

  1. 一次性新增全部公共文件（ffmpeg 执行器 / 探测 / 编码策略 / 规格校验 / 格式列表 / 前端组件）——只新增不碰旧代码，一个提交；
  2. 挑 1 个简单页面（建议「视频尺寸」）接入新组件做试点，一个提交；
  3. 试点回归通过（输出可播放、分辨率/比例正确、SAR=1）再接第 2 个（建议「视频优化」）。

风险最低的阶段：新代码不生效就不影响现有功能；试点验证行为一致后再推广。

2阶段

标签页分批迁移（按"低频→高频"）约 2~3 周每页一个提交

  1. 切片 / 截图 / 文字识别 / 人像检测；
  2. 音频混剪 / 视频混剪 / 拼接 / 去关键词 / 语音克隆 / 开拍云端；
  3. 裂变 / 视频优化 / 视频下载 / 字幕（复杂页面放最后，单独压测）；
  4. 最后简化主窗口的关闭清理逻辑（统一走 BaseTab 生命周期）。

每个页面迁移完跑一遍冒烟清单：路径输入、开始/停止、进度、结果表、配置持久化、主题显示。中途任何页面有问题只影响它自己，不影响已迁移页面。

3阶段

性能专项（先建基准、后优化）约 1~2 周每步对比耗时

  1. 先写基准脚本：同一批素材记录各模块当前耗时，存档（以后每次优化都有对照）；
  2. 按清单顺序：硬件编码 → 音频复制 → 并发 → 探测缓存 → 进度解析 → 去双编码，每步独立提交并对比耗时；
  3. 验收：尺寸调整/拼接/切片/去关键词/字幕较基线提速 ≥2 倍，全部功能冒烟通过。

NVENC 并发会话有限制，保留"自动/手动"开关和回退逻辑（裂变已验证过）。

六、明确不做 / 后置事项

不建议做（低性价比，避免踩坑）

  • 全量 UI 框架重写（换 QtQuick/QML 或其他框架）：收益低、风险高，与现有 16 个页面兼容成本巨大。
  • 引入 moviepy 替代 ffmpeg：现有全部代码基于 ffmpeg 命令行，换引擎风险大收益低；建议从依赖清单里移除未使用的 moviepy。
  • QSV 优先：本机实测 Intel QSV 反而比软件编码慢，保留 NVENC 优先即可，不用折腾。
  • 任务持久化 / 云端调度：单机桌面工具用线程池足够，「开拍云端」已是独立场景，不要强行统一。

可进待办池（不紧急）

  • 配置读写优化：现在每次保存配置都全量写整个文件，可改为按段写入 + 原子替换 + 备份。
  • 模型加载缓存：人像检测 / 文字识别 / 字幕的 AI 模型会话可跨任务复用，省重复加载时间。
  • gui/mix_tab.py（222 行，未注册进主窗口）确认为废弃后删除或迁移。
