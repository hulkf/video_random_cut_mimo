# 多视频合成性能优化

适用入口：桌面视频拼接、模板001、任务中心的 `video_concat` / `qianchuan_concat`。
调用方式不变；重启已打开的桌面程序后生效。任务中心后续新启动的执行器加载新代码，已经开始的任务不被中断。

## 本机测量

- Intel Core Ultra 9 185H，16 核 / 22 线程，约 32GB 内存，Intel Arc 核显。
- FFmpeg 8.1，原有代码在这台机器上使用 libx264 / ultrafast / CRF 23。
- QSV 可以运行，但同一段 10 秒素材的缩放编码诊断：CPU 1.96 秒，QSV 7.67 秒（包含进程/设备初始化）。本次保持原编码器和质量参数，不将短视频批次默认切换到 QSV。
- 业务样本：2622，3 个 1440×2560 模特视频，各约 7.1 秒；3 个非9:16平铺视频，各约 20～24 秒；封面固定0.3秒，生成3条1080×1920成品。
- 原流程首轮77.76秒，从Git原版源码独立复测85.99秒；优化后1路69.70秒、2路45.28秒、3路55.46秒。2路相比原流程减少约42%～47%耗时，约1.7～1.9倍吞吐。样本结果不能当作所有素材的固定倍数保证。

## 改动

1. 文件级有界并发，8逻辑线程及以上默认2路，小机器默认1路。每路合成编码和解码最多4线程，复杂滤镜2线程，避免每个FFmpeg都按整机线程数争抢资源。
2. 模板001将超过2000像素的目标尺寸提前设置为1080×1920，直接合成最终尺寸；保留最后尺寸检查和兜底处理。普通拼接及传统千川拼接保持原来的参考尺寸规则。
3. 已是9:16且不带旋转的输入直接只读复用；需要补背景或转正的素材仍转换到独立临时目录。重复文件名仍做区分，按原暂存文件名顺序配对。
4. 完成结果保持原配对顺序，独立任务异常不再派发剩余文件。回调在调用线程执行，暂停/停止时等待当前正在处理的文件结束，再清理临时目录；这不是立即终止编码。
5. 新增结果 `performance`：总耗时、并发数，模板另有归一化/拼接/尺寸检查耗时和复用输入数。传统千川拼接总耗时包含归一化。

## 调整和诊断

无需更改现有业务参数。需要手动控制时，正式计划步骤的 `options.batch_workers` 可填 `1`、`2` 或 `3`。不在界面增加必须填写的性能参数。

业务任务继续使用任务中心计划/确认/状态流程。开发诊断使用 `video_tool.py run --request -`，通过stdin提交新构造的JSON，stdout/stderr分开捕获；测试输出放在系统临时目录的独立目录，验证后清理。不要把测速输出写入正式素材输出目录。

回归覆盖有界并发、结果顺序、暂停/停止、失败不续派、重复输出名、跳过已完成、目标尺寸提前应用、复用与旋转处理；原有模板、CLI、任务中心和离屏Qt测试一并执行。

本轮160项测试通过。3条优化成品完整解码无错误，均为1080×1920且包含音轨，音视频末端时长差不超过20毫秒；原有封面/时长校验通过。画面抽查覆盖封面、模特段、平铺段；封面仍是随机抽帧，不要求与原版抽中同一帧。

传统 `qianchuan_concat` 另用独立临时目录中的一对真实素材通过CLI验证：归一化、只读复用、拼接和封面校验成功，成品仍按A素材保留1440×2560，未套用模板001专属的尺寸上限。
