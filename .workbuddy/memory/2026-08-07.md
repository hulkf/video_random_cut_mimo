## 视频下载 Tab 成功率优化（已提交 c26f5d8）

**诊断出的 4 个失败根因：**
1. 每个链接重启一次无头浏览器 → 慢 + 风控（baxia/滑块）命中率高
2. 直链判断 bug：只认 `cloud.video.taobao.com`，网络拦截到的 `cloudvideocdn.taobao.com` 真实 CDN 直链被丢弃，回退 u/0 通用模板对部分视频 404
3. `download_file` 零重试、吞异常，日志只有"下载失败"无原因
4. 提取失败不重试，浏览器状态卡死整批全挂

**修复内容（core/taobao_downloader.py + gui/video_download_tab.py）：**
- 线程内单例共享浏览器 `get_shared_browser()` / `reset_shared_browser()` / `close_shared_browser()`，atexit 兜底；worker 批量结束调用 close
- 网络捕获 handler 只挂一次（`net_hooked`），结果存 ctx['net_ids']/['net_urls']，每次提取前 clear
- 接受所有含 `.mp4` 的 http 直链；候选 URL 列表（直链→通用模板）依次尝试
- `download_file` 返回 (bool, err)，3 次重试 + 指数退避 + ftyp 头校验 + 清理过小残留文件
- 提取失败自动 fresh 重建浏览器重试一次

**实测**：短链 `e.tb.cn/h.8U3bu3MANeBUPcR` → 商品 1062426563110 → 视频 4013162174462240，两轮下载均 OK（~41s/轮），ffprobe 验证 h264 720x960+aac 20s。

**重要结论（未来参考）：**
- 免登录 mtop API（h5api.m.taobao.com mtop.taobao.pcdetail.data.get）被 RGV587 反爬拦截（x5secdata 质询），纯 requests 走不通，Playwright 方案是必须的
- 第三方 TaobaoVideoDownloader.exe 解包确认其也是同一思路（iPhone UA 抓 h5 页 + 同一 CDN 模板）
- 短链 e.tb.cn 解析：requests GET 后不跳转，从 body 正则 `itemIds=(\d+)` 提取商品 ID（现有 resolve_short_url 已覆盖）

## 第二轮：降级页识别 + 人工验证重试（已提交 1f62e65）

**用户关键情报**：淘宝识别爬虫后返回「降级页」——无视频、主图不全、无评论。3 条测试链接实际都有主图视频，看不到=被降级。

**实测验证**：
- 降级页实锤：商品1 正常时 SSR 有 5 张主图+视频字段；被降级后主图仅 3 张、`item.videos` 整个消失、20 秒轮询永不出现
- **有头浏览器也拿到降级页** → 标记在 IP/cookie 层面，换 headless=False 单独无效
- h5 移动版页面被惩罚时 goto 吃满 20s 超时（bixi punish 页）
- `mtop.taobao.detail.getdetail/6.0` 从 PC 页 SDK 调用成功但**从不带主图视频**（对照组验证）；`mtop.taobao.detail.data.get/1.0` 从 PC 页调用必超时
- 商品2(1062925069965) PC 端确实只有评价视频（rateVO），商品3(1050503150750) 是集市商品会 302 到天猫页

**本轮改动**：
- 短链解析新增 `var url='item.taobao.com/item.htm?id=...'` 直写式 + 长 id 兜底（`_extract_target_from_short_page`）
- 集市商品自动 item.taobao.com 打开
- 降级页识别日志（主图数/评论模块检查）
- 有头重试 + **人工滑块等待**（wait_for_human：轮询 SSR 视频字段最长 90s，用户完成验证后自动继续）
- 只找到评价视频也会触发 h5 页 + 有头重试找主图视频
- 删除从未生效的触发兜底方式3/4，单条省 ~20s

**调试脚本**（.probe/ 目录，可复用）：debug_item2b~l（SSR结构/mtop API探查）、debug_timing（延迟注入验证）、e2e_3links（三链接端到端）
